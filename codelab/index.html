Crea una app de IA en el dispositivo con Gemini Nano y ML Kit

Construye una aplicación Jetpack Compose que resume, corrige, reescribe, describe imágenes y conversa localmente mediante AI Core.

75 minutosIntermedioKotlinJetpack Compose

Antes de comenzar

Duración: 5 min

Construirás una aplicación Android en español que usa las APIs GenAI de ML Kit con Gemini Nano disponible en el dispositivo. No llama a un modelo de generación en la nube: AI Core administra la disponibilidad y la descarga de los componentes compatibles.

Aprenderás a

  • Configurar ML Kit GenAI en una app Compose.
  • Representar disponibilidad, descarga, generación y errores con Flow.
  • Aislar clientes de ML Kit en repositorios inyectables.
  • Mostrar resultados en streaming y liberar recursos correctamente.

Necesitas

  • Android Studio y JDK 17.
  • Un teléfono físico compatible con Gemini Nano y AI Core, Android 14 o posterior.
  • Conectividad durante la descarga inicial.
Comprueba primero la compatibilidad de ML Kit GenAI. La disponibilidad depende del hardware, Android, AI Core y cada API.

Obtén y ejecuta el proyecto inicial

Duración: 5 min

Abre el repositorio en Android Studio, espera la sincronización de Gradle y elige el teléfono compatible como destino. El módulo ejecutable es app.

android {
    namespace = "com.sdkecuador.gemininano"
    compileSdk = 36
    defaultConfig {
        applicationId = "com.sdkecuador.gemininano"
        minSdk = 34
        targetSdk = 36
    }
}

También puedes generar el APK de depuración desde la raíz:

./gradlew assembleDebug

La actividad instala solamente el tema y el grafo de navegación:

@AndroidEntryPoint
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent { AppTheme { AppNavigation() } }
    }
}
El proyecto puede compilar aunque AI Core no esté disponible. Por eso la app debe consultar el estado antes de solicitar una inferencia.

Añade ML Kit GenAI y crea los clientes

Duración: 10 min

Añade las APIs de cada capacidad en app/build.gradle.kts:

implementation("com.google.mlkit:genai-summarization:1.0.0-beta1")
implementation("com.google.mlkit:genai-image-description:1.0.0-beta1")
implementation("com.google.mlkit:genai-rewriting:1.0.0-beta1")
implementation("com.google.mlkit:genai-proofreading:1.0.0-beta1")
implementation("com.google.mlkit:genai-prompt:1.0.0-beta4")

Protege al resto de la app de las llamadas estáticas del SDK con una fábrica:

interface GenAiClientFactory {
    fun createGenerativeModel(): GenerativeModel
    fun createSummarizer(): Summarizer
    fun createProofreader(): Proofreader
    fun createRewriter(style: RewriteStyle): Rewriter
    fun createImageDescriber(): ImageDescriber
}

La implementación configura cada cliente. Este resumen acepta artículos en inglés y devuelve tres viñetas:

override fun createSummarizer(): Summarizer = Summarization.getClient(
    SummarizerOptions.builder(context)
        .setInputType(SummarizerOptions.InputType.ARTICLE)
        .setOutputType(SummarizerOptions.OutputType.THREE_BULLETS)
        .setLanguage(SummarizerOptions.Language.ENGLISH)
        .build()
)

override fun createGenerativeModel(): GenerativeModel = Generation.getClient()

Finalmente, vincula la fábrica con Hilt:

@Module
@InstallIn(SingletonComponent::class)
abstract class GenAiModule {
    @Binds
    abstract fun bindGenAiClientFactory(factory: MlKitGenAiClientFactory): GenAiClientFactory
}

Modela disponibilidad y descarga antes de inferir

Duración: 15 min

Una función no siempre está lista. Traduce el estado del SDK a un modelo propio y haz que todas las pantallas consuman la misma secuencia de operación:

sealed interface AiOperationState<out T> {
    data object Preparing : AiOperationState<Nothing>
    data class Downloading(val progress: ModelDownloadProgress) : AiOperationState<Nothing>
    data class Generating<T>(val partialResult: T? = null) : AiOperationState<T>
    data class Success<T>(val result: T) : AiOperationState<T>
    data class Failure(val error: AiException) : AiOperationState<Nothing>
}

Centraliza la preparación de cualquier capacidad:

internal suspend fun prepareModel(
    statusProvider: suspend () -> AiCoreFeatureStatus,
    download: suspend () -> Unit
) {
    when (statusProvider()) {
        AiCoreFeatureStatus.DOWNLOADABLE -> download()
        AiCoreFeatureStatus.AVAILABLE -> Unit
        else -> throw AiException.ModelUnavailable(...)
    }
}
No trates DOWNLOADABLE como listo. Espera a que finalice la descarga, comprueba de nuevo el estado y solo entonces genera contenido.

Implementa una capacidad especializada: resumen

Duración: 15 min

Un repositorio @ViewModelScoped posee el cliente, valida las entradas, prepara el modelo y emite estados para la UI:

@ViewModelScoped
class SummarizationRepository @Inject constructor(
    clientFactory: GenAiClientFactory
) : AutoCloseable {
    private val summarizer = clientFactory.createSummarizer()

    fun summarizeText(text: String): Flow<AiOperationState<String>> = aiOperation(
        validate = { validateTextInput(text, minimumCharacters = 400, maximumEstimatedTokens = 4_000) },
        prepare = ::prepare
    ) { onToken ->
        summarizer.runInference(
            SummarizationRequest.builder(text).build(), onToken
        ).await().summary
    }

    override fun close() = summarizer.close()
}

El ViewModel reduce los estados sin exponer el SDK a Compose:

viewModelScope.launch(Dispatchers.IO) {
    repository.summarizeText(text).collect { operation ->
        when (operation) {
            AiOperationState.Preparing -> setLoading()
            is AiOperationState.Downloading -> updateDownload(operation.progress)
            is AiOperationState.Generating -> appendPartial(operation.partialResult)
            is AiOperationState.Success -> showSummary(operation.result)
            is AiOperationState.Failure -> showError(operation.error.toUserMessage())
        }
    }
}
Llama a repository.close() en onCleared(). Los clientes ML Kit deben liberarse cuando acaba el ViewModel.

Añade el chat con Prompt API y streaming

Duración: 20 min

Para solicitudes personalizadas usa Generation. Limita la salida y valida el conteo real de tokens después de componer el prompt y el historial:

private suspend fun validatePromptTokens(request: GenerateContentRequest) {
    val inputTokens = model.countTokens(request).totalTokens
    val allowed = (model.getTokenLimit() - MAX_CHAT_OUTPUT_TOKENS).coerceAtLeast(0)
    if (inputTokens > allowed) throw AiException.InvalidInput(InputProblem.TEXT_TOO_LONG)
}

Emite fragmentos con generateContentStream():

fun streamResponse(prompt: String): Flow<String> = flow {
    requireAvailable(featureStatus())
    val request = GenerateContentRequest.Builder(TextPart(prompt))
        .apply { maxOutputTokens = 256 }.build()
    validatePromptTokens(request)
    emitAll(model.generateContentStream(request)
        .map { it.candidates.firstOrNull()?.text.orEmpty() })
}.requireResult()

En Generating, crea una burbuja vacía la primera vez y agrega los siguientes fragmentos a esa misma burbuja. De ese modo el usuario ve la respuesta mientras se genera.

Extiende la app a imagen, corrección y reescritura

La descripción multimodal combina una imagen y una instrucción:

val request = GenerateContentRequest.Builder(
    ImagePart(bitmap),
    TextPart("Describe esta imagen en una oración breve y objetiva.")
).build()
val description = generativeModel.generateContent(request)
    .candidates.firstOrNull()?.text.orEmpty()
Antes de inferir, ajusta las imágenes a 2 048 px por lado y 4 megapíxeles como máximo. Esto evita errores de entrada y presión de memoria.
